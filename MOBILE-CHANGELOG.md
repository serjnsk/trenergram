# Мобильная адаптация кабинета тренера — чейнджлог

Сверяйтесь с этим файлом, когда правите вёрстку или скрипты кабинета (`mvp/`): мобильная версия держится на нескольких неочевидных зависимостях, и десктопная правка легко ломает телефон.

- Дата: 12 октября 2026
- Охват: все страницы кабинета тренера — `index`, `calendar`, `clients`, `client`, `groups`, `exercises`, `exercise`, `blocks`, `workouts`, `programs`, `program`, `profile`, `constructor` (клиент / группа / шаблон блока и тренировки / мастер).
- Вне охвата: клиентское приложение `mvp/client/`, лендинг `mvp/landing/`, `design-preview` в ветке `main`; планшеты (761–1120 px) — остались в прежнем виде.
- Целевые размеры проверки: 390×844 (iPhone), 360×800 (Android). Десктоп 1920×1080 не должен отличаться от прежнего.

## 1. Принципы

1. **Десктоп не трогаем.** Вся адаптация — в двух новых файлах; каждое правило CSS лежит внутри одного `@media (max-width:760px)`.
2. **Разметку страниц не переписываем.** Страницы по-прежнему рисуют те же классы; телефонный вид получается переопределением CSS и небольшим JS-слоем.
3. **Зоны касания ≥ 44 pt**, шрифт полей ≥ 16 px (иначе iOS Safari приближает страницу при фокусе), нижняя навигация под большой палец, окна — шторками снизу (HIG).
4. **Плоский язык темы сохранён:** тон и линия, без теней (исключение — затемнение за шторками).

| `mvp/assets/mobile.js` | **Новый.** Нижняя панель, шторка «Ещё», шторка правой панели конструктора, кнопка «назад», сортировка списков, перетаскивание пальцем, умная липкая шапка календаря, блокировка автофокуса |

| `mvp/calendar.html` | Константа `HEAD()` (отступ при прокрутке к месяцу/дню) на телефоне считается как `52 + высота .monh`, а не как `58 + высота шапки календаря` — шапка календаря там уже не липкая постоянно |

## 3. mobile.js — что делает и от чего зависит

Скрипт подключён в `<head>`, а UI строит по `DOMContentLoaded`. Всё, что зависит от ширины, проверяется через `matchMedia('(max-width:760px)')`.

| Механизм | Поведение | Зависимости — что не ломать |
|---|---|---|
| **Нижняя панель `.mtabs`** | Три главных раздела (`index`, `calendar`, `clients`) и «Ещё» | Пункты берутся из массива `NAV` в `assets/nav.js` и иконок `ICON`. Новый раздел в `NAV` попадает в шторку «Ещё» автоматически; чтобы вынести его в панель, добавьте в `MAIN` в `mobile.js` (и учтите `grid-template-columns:repeat(4,1fr)` у `.mtabs`) |
| **Шторка «Ещё» `.msh`** | Остальные пункты `NAV` + профиль | Активный пункт берётся из `#nav a.on` (его ставит `renderNav`), запасной — из имени файла и карты `PARENT` (`client.html→clients.html` и т.д.) |
| **Кнопка «назад» `.mback`** | В шапке страниц `client`, `exercise`, `program`, `constructor`. Если пришли с той же origin — `history.back()`, иначе ссылка на раздел | Карта `BACK` в `mobile.js`. Шапку перерисовывает `renderTop()` — кнопку восстанавливает `sweep()` |
| **Шторка правой панели конструктора** | Кнопка `.mrail-btn` над днём, затемнение `.mrail-bd`, шапка `.mrail-x` внутри `.rail` | Селекторы `.rail` и `.cons main` в `constructor.html`. `#railhead/#src/#railfoot` перерисовываются страницей — сам `.rail` остаётся |
| **Сортировка списков `.msort`** | Вместо скрытой шапки таблицы — «Сортировка» + направление. Нажимает ту же `<th data-sort>` | Таблицы строятся `dataTable()` в `ui.js` (и `clients.html` с теми же `data-sort`). Логику сортировки не дублируем |
| **Пустые ячейки `.mnil`** | Ячейка с прочерком в карточке скрывается | Только таблицы `.tbl[data-tbl]` кроме `data-tbl="pm"` |
| **Перетаскивание пальцем** | Касание ручки `.gr` → `mousedown`, `dragstart`, `dragover`, `drop`, `dragend` с `DataTransfer`; автопрокрутка у краёв | Работает на родных обработчиках `trainer.js` (раздел «ПЕРЕТАСКИВАНИЕ») и `.cyc` в `program.html`. Ручка должна быть `.gr` внутри `.line` / `.blk` / `.doc` / `.cyc`. Если смените механику DnD в `trainer.js` — проверьте мост |
| **Умная шапка календаря** | Класс `.mhid` на `.calwrap .wkh` при прокрутке вниз | Структура календаря в `calendar.html` |
| **Блокировка автофокуса** | Подменён `HTMLElement.prototype.focus`: на телефоне игнорирует `focus()` для `input#q`, `.pane-h input`, `.dsel-s input`, `#cl-q`, если пользователь не печатал последние 600 мс | Страницы списков вызывают `focus()` после каждой перерисовки (иначе клавиатура выскакивала бы от тапа по фильтру). Новое поле поиска с таким же поведением добавьте в селектор |
| **`sweep()`** | `MutationObserver` на документе: `markNil`, `sortBar`, `backBtn`. На десктопе сразу выходит | Тяжёлый обход не добавляйте — вызывается на каждую мутацию DOM |

## 4. mobile.css — что изменено по областям

### Каркас и навигация
- `.app` вместо сетки — блок, `.nav` скрыт; `.main` получает отступ снизу `--tabh + safe-area`.
- Переменные: `--tabh:58px`, `--mtop:52px`, `--sab:env(safe-area-inset-bottom)`.
- Шапка 52 px; заголовок с многоточием; «Создать тренировку» — плюс 44×44 в акцентном круге (`font-size:0` + маска `::before`, подпись остаётся для скринридера).
- `viewport-fit=cover` дописывается в `<meta viewport>` скриптом (иначе `safe-area-inset-*` нулевые).

### Окна, всплывашки, списки выбора
- `.ov` прижат к низу, `.md` — шторка с закруглением сверху, макс. 92dvh; кнопка закрытия 44×44; подвал переносится, кнопки по 46 px.
- Шторками снизу стали `.sug.dsl` (выпадающие списки `dd.js`), `.sug.clipick` (выбор клиента), `.sug.dpick` и `.sug.dpk` (выбор даты), `.sug.setup` (формат блока). Позицию, которую `dd.js` и `nav.js` считают под мышь, перебиваем `!important`. Затемнение — `box-shadow:0 0 0 100vmax`.
- Подсказки у поля ввода (`.sug.exsug` и простой `.sug`) остаются у поля, но ограничены шириной экрана.
- Тост поднят над нижней панелью, `z-index:140`.

### Списки и таблицы
- `.tbl[data-tbl]` (кроме `pm`) → карточки: `thead` скрыт, строка — flex/grid. Подписи полей через `td:nth-child(n)::before`, **привязаны к порядку колонок**: клиенты (`cli`), группы (`grp`), базы (`lib-блок`, `lib-тренировка`, `lib-программа`), упражнения (`ex`). **Добавили или переставили колонку — обновите `::before` и номера `nth-child` в `mobile.css`.**
- Таблицы без `data-tbl` (замеры, платежи в карточке клиента, история платежей в профиле) остаются таблицами; замеры прокручиваются по горизонтали. В `pm` скрыта колонка «Обновлён».
- `.pane-h` на телефоне не липкий: сетка 2 колонки, поиск и кнопки на всю строку. Фильтры-чипы — одна горизонтально прокручиваемая строка.

### Дашборд
- KPI — 2 колонки; перерасход лимита — колонкой; вкладки `.tabs2` прокручиваются; событие ленты `.fev` — сетка «значок | текст», действие отдельной строкой под текстом.

### Календарь
- Месяц списком дней: `.days` в одну колонку, `.dow` и `.day.void` скрыты. Липкий заголовок месяца `.monh` под шапкой. Отметка дня (`.bk-box`) 24 px с зоной касания 44; строка массовых действий `.bk-bar` на всю ширину над нижней панелью (`left:8px !important`, потому что `bulk.js` ставит `left` инлайном).

### Карточка клиента
- Шапка колонками, контакты в 2 колонки, заметка колонкой, табы-якоря прокручиваются и липнут под шапкой (`top:var(--mtop)`; якорный скролл в `client.html` использует `HEAD = 58 + 52` — значение совпадает), две недели — карточки по две в ряд, оплата/замеры/максимумы — одной колонкой.

### Страницы элементов, профиль, группы
- `.ehead`, `.egrid` (боковая колонка уходит вниз, `sticky` снят), цикл программы `.cyc[draggable]` — сетка «ручка / номер / выбор / ✕ + мета / открыть».
- Профиль: `.prof` одной колонкой, `.side` без `sticky`, тарифы `.plans` колонкой, переключатель 50×30.

### Конструктор
- `.cons.cwide` — блок; `.rail` — фиксированная шторка (86dvh), `translateY(105%)` → `body.mrail-on .rail{transform:none}`; `.railtog` скрыт.
- Полоса недель `#strip` — горизонтальная прокрутка карточек по 150 px.
- Шапка дня `.doch` переносится, название на своей строке (`order:5`); шапка блока `.blkh` — две строки.
- Строка упражнения `.line`: название и ✕ первой строкой, схема и нагрузка `.prm` второй (`order:4`, отступ под ручку); ширину названия `--nmw` (выравнивание `alignNames`) на телефоне отключаем `width:auto !important`.
- Связка, суперсет (`.doc.quick .ssh …`), `.kind`-переключатель, `.pf`-поля — увеличены до 40 px.
- Панель сохранения `.pubbar` липнет над нижней панелью (`bottom:calc(var(--tabh) + var(--sab))`), подсказка `s` скрыта.
- Ручки `.gr` — `touch-action:none`, чтобы касание не прокручивало страницу.

## 5. Правила для разработчика

1. **Новая страница кабинета:** подключить `mobile.css` (после остальных стилей) и `mobile.js` (в `<head>`), вставить в `NAV` (`nav.js`), проверить на 390×844.
2. **Новая колонка в таблице-списке:** обновить подписи `::before` и `nth-child` в блоке «клиенты / базы / упражнения / группы» `mobile.css`. Не забыть про `mnil` (прочерк в ячейке скрывается).
3. **Правите `.doc.quick …` или другие правила с высокой специфичностью** — мобильные перекрытия должны быть не слабее (так сделано для `.doc.quick .ssh .ssf input`).
4. **Селекторы, на которые опирается JS:** `#topbar`, `#nav a.on`, `.rail`, `.cons main`, `.calwrap .wkh`, `.monh`, `.gr` + `.line/.blk/.doc/.cyc`, `th[data-sort]`, `.tbl[data-tbl]`, `.pane-h`. Переименование без правки `mobile.js` отключит соответствующий механизм молча.
5. **Новый `focus()` на поле поиска** — добавьте селектор в блокировку автофокуса, иначе на телефоне поднимется клавиатура.
6. **Новая всплывашка, привязанная к кнопке (`.sug …`):** если ширина фиксирована, добавьте её класс в список шторок.
7. **Инлайн-стили со страниц** (`style="width:260px"` и т.п.) перебиваются только `!important` — так сделано для полей `.pane-h`.
8. **Не использовать hover как единственный путь** к действию: на тач-экране его нет (кнопки `+` в панели календаря/баз для этого сделаны видимыми всегда).
9. **Заголовки и якорные отступы** с жёстким `58px` (шапка десктопа) на телефоне должны быть `52px` (`--mtop`).

## 6. Как проверять

- Скриншоты: headless Chrome не бывает уже 500 px, поэтому снимать страницу в `<iframe width=390>` на странице-обвязке (iframe не должен быть из `file://` на другую origin, если нужен доступ к DOM).
- Интерактив: панель браузера в Claude Code, `resize_window mobile` (375×812).
- Перед коммитом: прогон всех страниц на ошибки консоли (команда в памяти проекта `page-sweep-before-deploy`) и проверка на 1920×1080, что десктоп не изменился.
- Проверка переполнения: `document.documentElement.scrollWidth` не должен превышать ширину окна (учитывайте полосу прокрутки в iframe).

## 7. Известные ограничения

- Проверено в эмуляции Chrome; на реальных iPhone/Android не проходили. Особенно — перетаскивание в конструкторе и поведение клавиатуры в полях.
- Планшеты 761–1120 px: десктопное меню слева 238 px, как раньше.
- Перетаскивание дня (ручка в шапке дня) на день в полосе недель работает тем же мостом, но на телефоне полоса недель по умолчанию скрыта.
- Для тачпадов/гибридов: мост `touchDnD` срабатывает только на touch-события и только при ширине ≤ 760 px.

## 8. 14 ноября 2026 — стенд тренерского приложения и аудит

Мобильный вид кабинета станет тренерским приложением, поэтому все интерфейсы прошли повторный аудит — в том числе появившиеся после 12 октября (партнёрская программа, табы карточки клиента, меню «⋯» конструктора, окна приглашения и оплаты).

### Стенд `mvp/trainer/`

- `trainer/index.html` — стенд по образцу клиентского: карта экранов, телефон, описание. На телефоне сразу открывает кабинет.
- `trainer/map.js` — карта: 21 экран в 6 разделах, у каждого виды с шагами, которые стенд выполняет на странице (`trRun`: `click`, `js`, `type`, `wait`), признаки вида (`sel`) для синхронизации, блок «Адаптация». **Новый экран или окно кабинета — добавьте в карту.**
- Режим стенда страница узнаёт по `window.frameElement.dataset.mode` (`iphone:app`, `android:web`…) — атрибут на `<iframe>` переживает переходы по ссылкам. В режиме «Приложение» `mobile.js` задаёт `--sat` / `--sab` (59/34 у iPhone, 24/16 у Android), потому что во фрейме `env(safe-area-inset-*)` всегда 0; класс `html.in-stand` прячет полосу прокрутки.
- Режим тренера стенд передаёт через `?new=` и дублирует в `localStorage` (`tg.new`).
- «Новый» и «Шаги пройдены» — одно состояние кабинета (`trenergram.state.new`). При смене режима стенд его сбрасывает (`trMode`, ключ `tr.applied`), иначе «Новый» после «Шагов пройдено» открывался с отмеченными шагами; пока режим тот же — прогресс чек-листа сохраняется.

### Безопасные зоны (для приложения)

- `:root` получил `--sat: env(safe-area-inset-top)`, `--mtop` = 52 px + `--sat`, шапка — `padding-top: var(--sat)`. В мобильном вебе ничего не меняется (там `env()` = 0), в WebView приложения шапка не уходит под вырез и Dynamic Island.
- `calendar.html`: отступ прокрутки к месяцу на телефоне берёт высоту `.topbar`, а не 52 px.

### Исправлено в `mobile.css` (раздел «АУДИТ 14.11.2026»)

- **Карточки профиля и упражнения уже экрана.** Класс `.cb` у карточки совпал с пузырём чата блока (`pages.css`, 24 октября) — `max-width:75%/85%`, свой радиус и шрифт; на десктопе карточки профиля были 585 из 780 px. Исправлено в `pages.css`: правила пузыря действуют только внутри `.cbs` (`.cbs > .cb`). Задевало и админку (`admin/` подключает `pages.css`).
- **Сетка карточки клиента в списке не работала с 12 октября** — `[data-tbl="cli"] tbody tr{display:grid}` перебивалось `.tbl[data-tbl]:not([data-tbl="pm"]) tbody tr{display:flex}`. Селектор поднят; поля на постоянных местах: программа | составлено на, активность | группа, оплата.
- Шапка с датой (конструктор, тренировка клиента) — в две строки: название и дата; зона касания даты добрана `::after`.
- Окна: `.mdf .sp` скрыт — кнопки делят строку, длинная главная переносится во всю ширину; окно копирования дней — итог строкой, кнопки поровну.

- «Оплачено до» / «Группа» в карточке клиента — подпись у первой строки значения.
- Тренировка клиента: тип блока второй строкой под названием (`.wbh` — сетка).

## 9. 14 ноября 2026 — проход по HIG, компактный конструктор, длинные данные

Решения пользователя: все обязательные правки HIG, «+» в шапке по экрану, вариант 1 конструктора («Компактный»), защита от длинных данных — и на телефоне, и на десктопе.

### Конструктор — компактный вид (`mobile.css`, раздел «КОНСТРУКТОР · КОМПАКТНЫЙ ВИД»)

- Упражнение — одна строка: название слева, схема и нагрузка справа текстом, поля без плашек; пустые поля и «от–до» скрыты. Тап по названию или цифре — правка на месте (`.line.act`, его ставит `trainer.js`): у полей рамки, видны пустые поля.
- Ручки ⋮⋮ и ✕ — в режиме «Изменить» (`html.medit`), кнопку `.medit-btn` в шапку дня ставит `mobile.js` (`editBtn`) после каждой перерисовки дня.
- Ширина цифр по тексту: `field-sizing:content`, где есть; в Safari — переменная `--fw` (символов), её ставит `mobile.js` (`fitFields`).
- Над тренировкой: «Календарь и базы» — квадрат «Базы» справа от выбора клиента (сетка `.cons main:has(> .wk:not(.tplh))` — в режиме шаблона не включается); шапка дня одной строкой, статус значком; сообщение клиенту тонкой строкой; блоки без серой плашки, шапка блока одной строкой.
- Было: упражнение 102–106 px, тренировка из 37 упражнений — 10,7 экрана. Стало: около 50 px, 6,5 экрана.
- Селекторы от `#doc` — сильнее правил `.doc.quick …`. Меняете разметку строки (`.line`, `.prm`, `.pf`) — проверьте T1 в стенде.

### HIG (`mobile.css`, раздел «HIG 14.11.2026», и `mobile.js`)

- **Контраст ≥ 4.5:1** для мелкого текста: на телефоне `--ok:#147A46`, `--warn:#8A6200`, `--acc-d:#B83D00` (усиленные варианты тех же оттенков, как Increased Contrast у Apple); цифры на плитках, стрелка сортировки и ссылки шагов «Первые шаги» — `--acc-d`; дни соседнего месяца — `#6C6C70`. Яркий `--acc` остаётся заливкой и значками (белый жирный на нём — 3.3:1, порог для жирного 3:1).
- **Зоны касания 44 pt**: у компактных элементов — невидимая рамка `::after` высотой 44 (только по вертикали, чтобы соседние не перекрывались); поля, шапки блока и дня, кнопки «+» в «Базах», табы — 44 px. Новый мелкий элемент — добавьте в список или дайте высоту 44.
- **Шторки**: хват у окон (`.ov .md::before`), закрытие смахиванием вниз за верхние 56 px — окна, «Ещё», «Календарь и базы», выбор клиента и даты (`mobile.js`, `SHEET`/`closeSheet`). Короткий рывок возвращает шторку. ✕ и затемнение остаются.
- **Клавиатуры**: телефон `type=tel`, email `type=email`, пароли `autocomplete=current-password/new-password`, имя/фамилия/город — автозаполнение (`profile.html`); 1ПМ, 3ПМ, замеры — `inputmode=decimal` (`client.html`).
- **VoiceOver**: кнопкам-значкам с одним `title` `mobile.js` (`names`) ставит `aria-label`; кнопкам без подписи — по назначению (`[data-del]` → «Удалить упражнение» и т. п.).
- **Уменьшение движения**: под `prefers-reduced-motion` переходы и анимации мгновенные, шторка при смахивании закрывается без анимации.

### «+» в шапке по экрану (`mobile.js`, `plusBtn`)

На компьютере «+» везде — «Создать тренировку». На телефоне: Клиенты → «Пригласить клиента», Группы → «Создать группу», Упражнения/Блоки/Тренировки/Программы → добавить в базу (нажимает ту же кнопку страницы), дубль в списке скрыт (`#btnAdd`, `#gNew`, `.invw:not(.spot)` — подсветка онбординга остаётся); календарь и карточка клиента → тренировка этому клиенту/группе; профиль, упражнение, программа, конструктор, тренировка клиента — без «+». **Новая страница-список — добавьте в `PLUS` или `NOPLUS`.**

## 11. 14 ноября 2026 — тренерское приложение: экраны заново (`mvp/trainer/app.html`)

Мобильный вид кабинета остаётся запасным «кабинетом в браузере телефона»; приложение проектируется заново по задачам тренера (состав — решения 14.11). Стиль — Strava iOS (референсы Mobbin): белые экраны, карточки во всю ширину на сером фоне, заголовок по центру, оранжевые подчёркивания и пилюли. Компоненты — по HIG (касание 44 pt, текст ≥ 4.5:1, шторки с хватом). Данные и логика — общие с кабинетом (`data.js`, `nav.js`, `ui.js`): что сделано в приложении, видно в кабинете и у клиента.

- **Файлы**: `trainer/app.html` (оболочка), `app.css` (стиль), `app.js` (экраны, маршруты `#/today`, `#/calendar`, `#/clients`, `#/client/<id>`, `#/group/<id>`, `#/workout/…`), `editor.js` (редактор тренировки `#/edit/<кто>/<дата>`). На стенде — раздел «Приложение · новый дизайн» (A1–A6).
- **Сегодня (A1)** — два модуля на сером фоне. Виджет «Тренируются сегодня · 24» отдельной карточкой: три статуса значком в углу аватара — ▶ в процессе (записал часть результатов), ✓ выполнили, ещё не начинали — без значка; времени занятия в данных нет, поэтому ни время, ни «опоздал» не показываются; черновики сюда не попадают, «Все» — шторка по статусам; при прокрутке сворачивается в строку под заголовком. Раздел «События» со своим заголовком, счётчиком новых и фильтром: карточка одного формата — аватар, имя, одна серая строка, метка типа справа вверху (значок и слово, цвет по смыслу), одна-две фразы, одно действие (мягкая кнопка, если нужно действовать, иначе ссылка). Новые — оранжевая точка; просмотрено, когда карточка побыла на экране (`STATE.appSeen`), точка гаснет при следующем открытии экрана; бейдж вкладки — сколько ещё не видели.
- **Первый вход (A1, Тренер: Новый)**: модуль «Первые шаги» первым на «Сегодня», не выше половины первого экрана (42 % на 360×780): прогресс сегментами и горизонтальная лента карточек шагов, следующий — первым; пять шагов (ответить на вопрос демо-клиента, добавить упражнение в демо-тренировку, создать ему тренировку, добавить рекорд, пригласить клиента), отметки по фактам из данных, свернуть/убрать. Демо-клиент — «Демо Клиент». Демо-события: в ленте только сегодняшнее — «подключился по ссылке» и вопрос к блоку сегодняшней тренировки (`talkSeeds` в `data.js` в режиме нового тренера), демо-клиент «в процессе». Рекорды клиента правятся шторкой из карточки (A4).
- **«Результат» и «Не закрыли»**: результат — отдельное событие на каждого клиента, закрывшего тренировку; утром — одно событие со списком тех, кто не закрыл вчерашнюю, в шторке «Написать» каждому. Тип «Программа» в ленте приложения убран.
- **Календарь (A2)** — под два сценария: найти прошлую тренировку и скопировать, посмотреть чью-то. Шапка: значок копирования (выбор нескольких дней), имя клиента/группы с ▾, «+». Сетка — две недели (⌄ — месяц), легенды нет, точки трёх цветов: зелёная — выполнена, красная — пропущена, оранжевая — опубликована (черновик — контур); под сеткой тренировка выбранного дня одной карточкой: статус словами, «Открыть»/«Посмотреть» и «Копировать», сообщение клиенту, блоки в формате клиентского приложения — по умолчанию свёрнуты (название, стрелка, число упражнений), «Развернуть все» над ними; развёрнутый блок — строки «схема упражнение вес», группы через линию. В шторке «Не закрыли» строка ведёт в тренировку клиента. Несколько дней — значком копирования в шапке или долгим нажатием (копировать, опубликовать, скрыть). После «Копировать» сразу режим вставки: одна тренировка — в любые дни, несколько — с первого дня с теми же промежутками, клиента можно сменить; занятые дни предупреждают; копии — черновики. Бейдж новых: всё, что раньше первого открытия приложения, — просмотрено (`STATE.appSeenFrom`).
- **Клиенты (A3) и карточка (A4)**: список «Требуют внимания / Все остальные»; в строке только имя и под ним статус, если есть (программа — в карточке); фильтр по статусам и сортировка — значком у поиска и шторкой, как на «Сегодня»; смахивание строки («Получил оплату», «Написать»), группы; карточка — быстрые действия, «Сейчас», оплата, заметка, рекорды.

Строка показывает итог («5×3 · 80 % → 96 кг»), правка — в шторке (схема с готовыми вариантами, нагрузка с единицей, от–до, пересчёт от 1ПМ, своя запись). Поиск по базе с недавними упражнениями клиента, несколько сразу — по отдельности, сетом или связкой; тип блока и настройка комплекса со степперами; блок текстом с разбором ИИ под полосой «Проверьте»; из шаблона, из календаря (своего или другого клиента).
